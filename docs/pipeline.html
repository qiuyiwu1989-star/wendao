问道 · 系统说明

推理管线

一句话从麦克风到耳朵，中间经过八道工序。整条链路的设计目标只有一个： 让"你说完"到"听见第一声"控制在 3 秒内，而不牺牲教练的锋利。

主链路

听 → 识别 → 装配 → 生成 → 切块 → 合成 → 播放 → 回到听

提示词是怎么拼的

同一个大脑，两种装法——语音要快，打字要深

三条旁路

不在主链路上，但决定问道能不能"越用越懂你"

向下取

对话前，调你的背景

去深脑检索相关的既有判断，拼进提示词，于是它问出的是"懂你"的问题。检索要 3–4 秒，所以设了硬超时——到点就走，后台跑完存缓存，下一轮直接命中。

收尾

一场结束，提炼成判断

用问道自己的引擎，把这场对话里"你想清楚了什么"固化成判断（想清楚了／还在赌／待解），每条附你自己的原话做依据。既是你能带走的，也是喂给深脑的弹药。

向上喂

沉淀跟着你走

小结存进问道自己的表、按账号隔离；深脑用同一个账号即可读到。不用一把全局钥匙往别人大脑里写——那是越权。

延迟预算

服务器侧实测中位数。优化的依据是分段测量，不是猜

最大的一块省在第一句的长度上。原来首句 43 个字——首字 1.5 秒就出来了， 却要等整句凑齐才肯开口，白等两秒。让它先说一句短的接住你，再展开，这一条就省了 1.26 秒。

护栏在哪

每一道都挡在花钱或泄露之前

/api/chat
限流 30 次/分/IP，按 nginx 注入的真实 IP 分桶——取转发头的第一个值可被伪造，那是我修过的高危漏洞。
取背景 · 投喂
必须已登录且在白名单，默认关闭。服务端只有一把深脑钥匙，不设门禁等于所有访客都在读同一个人的隐私。
提示词第 0 层
危机识别：用户流露严重痛苦时停掉全部教练动作，接住他，把国家心理援助热线递过去。这条压过"要简短""不给答案"。
/api/asr
上传 8MB 上限，挡内存耗尽。
渲染层
模型输出经消毒后才插进页面，防止被诱导吐出可执行脚本。
全链路
密钥只在服务端，前端拿不到；应用只监听本机，一律经反向代理。
